# 架构

状态：已贯通文档转换、预览和持久化打印流程；本地、虚拟设备与实体设备的验证分别记录。

## 产品流程

微信扫打印码 -> 微信原生隐私授权（按需）-> 选择文件 -> 上传和准备文档 -> 预览及设置 -> 创建打印任务 -> 查看进度。
手动双面任务在第一轮后等待用户翻纸，再执行第二轮；新设置默认偶数面先印。
地址、访问凭据由部署者写入打印码，普通用户不填写地址或配对码，也无需重复扫码。
扫码解析后先等待微信隐私确认，再获取登录 code 和申请会话，不增加独立登录页或自制授权弹层。
`pages/connect/index` 保留为已有小程序码的入口路由；外部扫码带入目标时不再显示扫码按钮。
没有目标且无有效会话的直接打开才显示扫码入口，已有有效会话的普通重入恢复打印机页。
M1 只贯通到打印机能力读取；文件流程从 M2 开始。

客户端一次编辑、确认一份文件。文件选择页仅负责选取和上传，成功后被打印设置页替换；
预览、参数和打印确认集中在设置页，返回直接回到打印机列表。
“重新上传”在当前设置页内选文件并上传，成功后替换文档、恢复默认参数；
新文件默认优先使用设备支持的黑白模式，用户可手动选择彩色；重新上传同样恢复黑白。
设备未报告黑白能力时保留队列默认或已报告模式，不添加未知能力。
取消或上传失败保留原文档和可用预览。它不建立新的页面层级或多文件收件箱。
打印机信息由卡片的 `i` 图标进入独立页面，不再放在详情下拉中。
卡片直接显示当前授权的未完成任务，主操作切换为“继续任务”；结束后恢复“选择文件”。
小程序不提供历史列表。服务端保留短期任务记录、调度及等待翻纸的保护；
微信身份模式下，同一用户在同一打印机只能新建一个未完成任务；
兼容匿名模式仍按会话区分。客户端单文件流程不表示打印机全局独占。

一个仓库包含两个应用：微信小程序和 Go 服务。Go 服务作为一个进程部署，直接接入已有 CUPS。
模块化用于划分代码职责，当前没有拆成多个网络服务的需要。

## 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `api` | HTTP、身份上下文、输入校验、错误映射 | SQL、PDF 页序、命令执行 |
| `documents`（M2/M5） | 原文件与转换结果生命周期、页数、所有权、分页缓存及过期 | 创建打印任务、微信交互 |
| `pdf`（M2/M3/M5） | Office/图片转换、PDF 布局与阶段文件、Poppler 页数及栅格化 | 生命周期、页面选择规则、HTTP、CUPS |
| `printing`（M3） | 打印设置快照、页面安排、任务阶段和调度 | HTTP、SQL 细节、IPP 编码 |
| `cups`（M1） | 打印机能力、IPP 提交/查询/取消 | 手动双面产品流程 |
| `canonstatus`（可选 CUPS monitor） | 原样转发打印流、解析 Canon 回传并向 CUPS 报告缺纸 | HTTP、文档、页序、提交或恢复任务 |
| `pairing`（M1） | 扫码凭据交换为会话、校验与撤销授权 | 微信入口路由、文档转换、打印调度 |
| `accounts` | 稳定用户、可选称谓或昵称、封禁、管理员与新打印开关 | HTTP、微信网络协议、物理队列变更 |
| `wechat` | 服务端 code2Session 交换与错误隔离 | 任务归属策略、客户端凭据 |
| `management` | 受机主权限保护的看板和任务取消 | 文档内容读取、驱动/电源配置 |
| `printers`（M1） | 与 IPP 无关的打印机能力数据及失败类型 | 协议编解码、打印任务调度 |
| `store`（M2/M3） | SQLite、有序迁移、文档/打印记录与会话摘要适配 | 决定任务能否继续 |
| `app` | 配置、构造依赖、启动和关闭资源 | 具体打印规则 |
| 小程序 `services`（M1） | HTTP、上传、轮询和错误转换 | 页面状态和页序算法 |

`api` 调用业务入口；业务入口在需要外部能力时定义小接口，由具体适配器实现，`app` 负责连接。
不为每个函数都建立接口，也不先做插件框架。纯页面计算优先使用普通函数和不可变输入。

## 核心对象

- **文档**：上传的原始文件及其准备结果。用稳定编号引用，浏览预览不创建打印任务。
- **准备结果**：转换后的 PDF、页数、预览及影响布局的参数版本。相同输入和参数可复用。
- **打印任务**：固定的准备结果、打印机和参数快照，以及阶段状态、CUPS 作业编号。
- **页面安排**：每张纸正反面对应哪些文档页面、顺序及旋转。由 `printing` 统一计算。
- **设备校准资料**：进纸、出纸堆叠和翻纸动作的实测结果；与某次任务的参数分开保存。
- **翻纸配置**：部署者按队列指定的带版本处理方案；目前支持后进纸、正面朝上出纸。
  配置本身不代表实测验收。服务端将它解析为任务参数快照，小程序只展示对应放纸图示。

单面、自动双面和手动双面共用打印设置及页面安排。设备差异通过能力和校准数据表达，
不能在小程序页面里堆型号判断。新增客户端继续使用同一套文档和打印任务接口。

## 文档和预览

原始文件与准备结果分别保存，转换输出使用原子交接，不能让预览读到写了一半的文件。
排版相关参数变化时生成新准备结果。打印任务引用确定版本，后续修改设置不改变已创建任务。
分页图由服务端渲染，支持按需生成和缓存；变换后的 PDF 作为预览和打印的共同来源。
打印预览将计划中的 `monochrome` 和 `auto-monochrome` 栅格化为灰度，
`color`、`auto` 和未指定模式保留原色。原始文档预览不应用打印参数。
颜色预览缓存使用独立版本，旧计划也按保存的模式重新生成，避免读取旧彩色缓存。
此处理不改写 PDF；实体打印的颜色仍由 CUPS 的 `print-color-mode` 处理，
预览不模拟驱动色彩管理、墨水配比或自动模式的最终选择。
设置页按阅读顺序显示排版结果，`printing` 将阅读索引映射到同一 PDF 的实际纸面；
倒序出纸不改变阅读顺序。预览不展示软件为双面配对补出的最后空白面，
保留原稿空白页和拼版空白格。`pageCount` 仍含配对空白，`previewPageCount` 不含；
分页接口省略顺序保持旧语义，小程序明确请求 `order=reading`。
PDF 适配器在创建打印副本时不迁移将因拼版失效的命名目标，不修改原始上传文件。
小程序设置变化后自动准备预览，防抖和串行请求避免连续修改堆积，过期结果不能启用打印。
同一编辑过程通过 `replacesPlanId` 替换同属会话/文档的未提交计划；失败不删除前一结果，
活动任务引用的快照保留。打印仍是独立确认动作，预览更新不改变滚动位置。
终态任务在下一次成功清理时回收阶段文件。没有其他活动任务引用同一文档时，
同时回收原文件、转换结果、预览和相关计划；未提交文档默认 24 小时过期。
终态元数据与幂等键保留 3 天。活动任务创建满 3 天先进入取消核对流程，
不直接删除无法确认结果的任务文件。CUPS 缓存和部署备份属于独立的副本保留范围。

PDF、图片和 Office 文档共用此流程。转换错误明确返回，
不能在页数解析失败时伪装为一页或把尚未生成的预览报告为成功。
转换器应可测试，执行外部工具有并发限制、超时和独立工作目录。

## 打印任务与设备

上传、转换、预览均不得调用打印提交接口。只有用户确认创建打印任务才产生打印副作用。

手动双面流程的核心阶段是：

```text
queued -> printing -> awaiting_flip -> printing -> completed
```

实际状态设计在 M3/M4 随实现确定，并覆盖取消、失败、设备离线和结果不确定。
记录 CUPS 接受任务与物理打印结束的区别，展示设备实际能确认的状态。
缺少可靠完成反馈时要求用户确认纸张已经输出，不提前自动推进翻纸阶段。

可选的 Canon port monitor 由 CUPS 启动，通过标准回传管道报告缺纸，
不进入应用服务生命周期。任务页通过既有 IPP 适配结果显示一次性缺纸弹窗；
关闭弹窗不改变任务，补纸恢复仍按设备面板提示处理。
坏报文、状态未知和请求失败不作为恢复证据，设备之外的遥测能力不由此推定。

页面安排先应用页码选择和布局，再决定正反面，处理奇数张、空白面、多份和翻转方向。
`outputOrder` 在拼版及补空白后按整张纸重排，保留每面的阅读顺序及正反配对；
小程序新设置默认倒序。`manualFirstSide` 决定手动双面哪一面先印，新设置默认偶数面；
缺省保持旧任务的奇数面先印。`phase` 始终标识逻辑正反面。
手动翻纸的 `backOrder` 和 `backRotation` 应用于第二轮；旧的奇数面先印任务语义不变。
已经抽取或重排的输出文件不再附加原始奇偶页过滤。G2810 的顺序必须经过实测校准。

同一打印机在等待翻纸时，PrintBridge 暂缓自己的其他任务。直接来自系统打印或其他 CUPS
客户端的作业不受本服务的内部锁保护，不能宣称全局独占；需要在适配和操作说明中明确。
打印机读取接口同时给出本服务占位状态与待提交数量，不返回其他用户的任务资料。
缺纸是共享打印机原因，后续任务继续等待并显示原因；任务自己的 CUPS 状态快照
区分 pending 和 processing，只有实际正在处理的任务弹出补纸提醒。
空闲、未知和断开的旧缺纸原因以历史报告展示，不作为实时设备状态。

任务状态持久化。重复点击和重试不得创建重复任务；服务重启后通过记录的 CUPS 作业核对。
提交结果不确定时先进入核对状态，不能盲目重发。第一次实现打印副作用时就完成这条恢复路径。

取消的 CUPS 终态也不等于 USB 后端退出或设备缓存清空。已提交任务维持取消中，
等待队列空闲；可能已到达设备的数据由明确启用的设备适配器自动清理，成功核对
实时设备空闲后才解除占位。G2810 适配使用指定 USB 接口软复位及连续状态回报；
失败或不支持时保留取消中并重试。小程序不要求面板停止确认。
新任务提交和释放前同样核对空闲状态；未知、断开和暂停均不自动放行。
旧人工确认接口只为无适配器的既有部署保留，不能绕过已配置的自动验证。
客户端重入和服务重启不跳过保护。
本机显式缩短 CUPS 的 JobKillDelay，调度器负责结束已取消但不退出的后端，
随后仍经过上述设备确认。该设置影响整个 CUPS 服务，不自动应用于其他部署。

## HTTP 与访问

- 已实现接口以 `api/openapi.json` 为准；业务接口使用 `/api/v1`。
- 错误格式统一为 `{"error":{"code":"...","message":"..."}}`。
- 无授权可读取进程和版本信息；扫码入口等待微信隐私确认后才申请会话。
- M1 为队列信息加入会话授权，M2 的上传和分页图也验证授权及文档所有权。
  管理员凭据不分发到小程序，文档服务不提供公开文件目录或含令牌的图片链接。
- 微信入口、地址解析、隐私确认、会话授权在代码中分工；外部扫码后由微信按需显示原生同意弹窗，
  无需再扫码、另点登录按钮或手工填写连接信息。
  授权仍由服务器校验，客户端打开页面本身不代表授权成功。
- 初版采用局域网连接；远程访问作为另一个有独立验收条件的增量。

部署可采用隔离访客网：访客网关仅将打印端口转发到主网服务，
同时保留主网直接访问。打印码可选 `alternateServers`，最多三个备用私有 IPv4 origin。
隐私同意后，扫码服务根据 `wx.getLocalIPAddress` 的地址和真实掩码选择唯一同网段入口，
不尝试向其他地址发送配对码或登录 code。旧单地址码保持原行为。
网段未知、无匹配或不唯一时保留原会话并提示重试；换 Wi-Fi 后重新扫码，
服务端稳定身份恢复任务。已保存令牌不自动改投备用 origin。
网络隔离与限速由部署网络负责，不进入 HTTP、文档或打印业务模块。

启用微信身份后，入口调用 `services/privacy` 等待 `wx.requirePrivacyAuthorize` 成功，
再由会话服务取得一次性 `wx.login` code；使用微信官方弹窗，不绘制自己的授权界面。
是否需要重新同意由微信决定，已同意且无需更新时不强制重复弹窗。
主动查看隐私保护指引的入口位于“我的”底部，扫码连接页只显示连接状态和重试/扫码操作；
查看指引使用微信原生页面，不依赖账户读取成功，也不触发登录或打印。
拒绝同意或不支持隐私接口时不登录，不回退为匿名身份。服务端确认 OpenID，
以 `(AppID, OpenID)` 映射到 SQLite 中稳定用户编号。新会话、重新编译和重启不改变 owner。
每次授权检查都会读取封禁状态。底栏为“打印 / 我的”，不提供独立退出入口；
日常重入复用有效会话，需要更换设备时从打印页扫码，新连接成功后再撤销旧会话。
称谓或昵称在“我的”页内自愿填写，点击保存或清空后保存到服务端，不弹出填写提示；
这是用户自定义的显示称呼，不校验真实姓名，也不自动获取微信昵称。
API 和数据库继续使用已有 `name` 字段，兼容已保存的内容。
已有 `namePrompted` 字段保留兼容，不再驱动客户端交互。
页面显示的打印账户编号是随机内部 ID，原始 OpenID 不进入客户端响应。
管理员是服务端配置的唯一用户，业务入口也检查权限；看板不提供文档内容或原始 OpenID。
未配置微信凭据的旧部署仍保留匿名模式，明确不提供跨会话恢复及用户管理。

## 维护边界

转换工具、CUPS 和 SQLite 是外部适配点；业务状态与页面安排保持独立测试能力。
加入依赖应固定版本并保留必要许可。数据库变更使用有序迁移，提供升级前备份和失败处理说明。
API、新配置、迁移和部署要求随对应功能更新，不能只改代码。
