# 数据升级与回退

## Schema 1：M2 文档元数据

来源：`server/internal/store/migrations/001_documents.sql`。

首次启动在 `PRINTBRIDGE_DATA_DIR` 创建 `printbridge.db`，通过事务创建 `documents`
及过期索引，并设置 `PRAGMA user_version=1`。已有 schema 1 不重建。
发现大于当前支持的 schema 版本时拒绝启动，不静默降级或删表。
schema 1 只保存文档编号、会话摘要、名称、字节数、页数和创建/到期时间，不保存会话原令牌。

文档文件位于同一数据目录的 `documents/<id>/source.pdf` 与 `page-<n>.png`；
不得只迁移数据库而遗漏文件。文件所有权按服务运行账号设置，数据目录不要作为静态网站公开。

## 升级

1. 停止 PrintBridge，等待请求和后台清理结束。
2. 备份整个数据目录，包括数据库、仍存在的 WAL/SHM 文件及 `documents/`。
3. 保留原服务配置和二进制，换用新版本。启动会执行尚未应用的有序迁移。
4. 先检查元信息、重新扫码，再用合成文件验证上传和预览。上传不会创建 CUPS 作业。

M1 没有数据库，升级到 M2 无需迁移旧业务数据。M1 的易失会话在更新时失效，需重新扫码。
默认数据目录相对于进程工作目录；改变工作目录时应显式配置相同的 `PRINTBRIDGE_DATA_DIR`。

## 回退

当前不提供自动降级 SQL。回退到 M1 时停止服务、保留 M2 整个数据目录备份，
运行原二进制和配置；M1 不读取它。再次回到 M2 时 schema 1 可继续打开，但已过期文档会被清理。
旧 M2 重启后不能凭新会话恢复旧会话的文档，不把数据库持久化描述成跨会话任务恢复。
后续 schema 升级若需要回退，应在停机后恢复相匹配的完整备份及旧二进制，不能只修改 user_version。

## Schema 2：打印任务与会话

来源：`server/internal/store/migrations/002_printing.sql`。按顺序在同一迁移事务中应用；
保留 `documents` 表，增加 `print_plans`、`print_jobs` 和 `sessions`。
任务的 `(owner, request_key)` 有唯一约束。Plan/Job 的业务快照保存为 JSON，
所有权与幂等键在独立列保存；会话只保存 token SHA-256、访问码 SHA-256 和到期时间。

文件增加 `documents/<id>/original`、`printing/plans/<id>/layout.pdf`、
`printing/jobs/<id>/{single,front,back}.pdf`。已有 M2 source.pdf 继续可读，
不要求缺少 original 的历史文档重建。Plan 24 小时到期。
2026-10-21 起终态文件在下一次成功清理时回收，终态元数据与幂等键保留 3 天；
活动任务创建满 3 天先取消并核对，结果不确定的任务不会由清理擅自丢弃。
首次从 M2 升级需重新扫码；此后相同数据目录、访问码和未到期会话可跨重启恢复。
重新扫码获得的新会话不能认领旧会话的任务。

备份须包含整个数据目录。在有活动打印任务时先核对 CUPS，完成或取消任务后再升级/回退；
恢复旧数据库可能回到过去的作业状态，必须保留 CUPS 历史供核对，不能把未知提交重新发送。
本次不提供降级 SQL。回退到 M2 必须恢复 schema 1 的完整备份和对应二进制，
不能对 schema 2 仅修改版本号。只操作当前数据目录，不修改打印机队列或驱动。

## Schema 3：持久用户与机主管理

来源：`server/internal/store/migrations/003_accounts.sql`。
新增 `users`，以 `(app_id, open_id)` 唯一识别用户，保存随机内部编号、用户自填姓名、
提示选择、封禁、创建及最近登录时间；会话增加 `user_id`。
`account_settings` 保存新打印开关，初始开放。三项变更与版本号在同一事务提交。

原有文档、计划、任务及会话仍保留。旧会话的 user_id 为空：
无微信凭据模式下继续按原 token 摘要使用；启用微信后拒绝它们，
要求重新扫码取得已验证身份。旧 owner 不推断或批量迁移到某位微信用户，
管理员可在看板确认取消遗留任务。尚无跨用户任务认领接口。

沿用完整停机备份步骤，先完成或经操作者确认取消活动任务。
升级后配置真实 AppID/AppSecret，用户登录后复制“我的”中的编号，
在私有配置设置唯一 `PRINTBRIDGE_ADMIN_USER_ID` 并重启，绝不把首个访问者设为管理员。
先升级后端，再使用新版客户端；新版客户端能显示旧部署尚未启用身份登录。

回退到 schema 2 必须恢复升级前完整数据、配置和旧二进制；旧二进制拒绝 schema 3。
不得删掉用户表或只改 user_version。用户记录不按打印文件 TTL 自动删除，
否则稳定身份和封禁会丢失；部署者需按隐私说明独立管理账号删除与备份期限。

2026-10-21 的当前任务与文件保留策略仍使用 schema 2。升级前备份完整数据；
旧终态文件和超期元数据可能在首次启动清理时回收，回退二进制不能恢复这些内容。
备份本身也包含用户文件，不属于在线清理已删除的副本，需单独管理其期限。
见 [ADR 0013](decisions/0013-current-task-and-retention.md)。

## Schema 2 内的首轮纸面设置

2026-10-19 增加 JSON 设置 `manualFirstSide`，无 SQL 迁移。旧任务缺省继续先打印奇数面，
新小程序显式选择先打印偶数面；任务恢复和翻纸确认依据自身快照，不跟随客户端默认值变化。
小程序校准缓存使用 v2，重新确认首轮纸面与第二轮顺序/旋转后保存。

先升级服务端，再重新编译客户端。旧服务端不理解偶数面先印任务，
回退前必须完成或取消新任务，并按上述流程备份、核对 CUPS；schema 相同不等于能直接降级。
