# M2 PDF 准备验证

日期：2026-10-14

范围：源码、Windows 服务、临时 SQLite、合成 PDF 与真实 Poppler。

## 已验证

- `server/` 下 `gofmt`、`go vet ./...`、`go test -race ./...` 通过。
- SQLite 初始化 schema 1、重开后元数据保留、删除和拒绝较新 schema 均通过。
  初次检查发现 Windows `file:` URI 的盘符被解释为 authority，修复后含空格路径的实际数据库测试通过。
- HTTP 覆盖单个 multipart PDF、文档 metadata、PNG、HEAD、无效页、超大小、多文件、
  工具失败/超时、所有权、会话撤销、渲染中撤销和缓存命中后的授权检查。
- 生命周期测试覆盖 16 页、错误页数、页数上限、失败上传和渲染产物清理、
  分页缓存、到期禁止访问、清理中断上传目录、保留有效文档及并发操作限制。
- 工具适配器使用受控测试子进程，覆盖加密/无效 PDF 输出、超页数、缺少工具、
  超时和输出长度限制；不调用任何打印命令。
- `PRINTBRIDGE_TEST_POPPLER=1 go test ./internal/pdf -run TestPopplerWithSyntheticDocument -v`
  实际执行通过，非 skip。本机 Poppler 为 26.07.0；合成 PDF 正确解析 3 页，
  第 2 页为横向，每页最长边不超过 1600 像素，三张输出不同。
- 本机 Windows HTTP 服务实际完成授权、上传合成 PDF、读取 metadata、下载三张 PNG、
  再次读取相同页面且内容一致、撤销后访问已缓存页面返回 401。
  三张实际 HTTP 输出均已人工视检：文本、边界、页码完整，横竖方向正确。
- `miniprogram/` 下类型检查及 50 项行为/工程检查通过，其中 10 项为文档流程新增覆盖。
  模拟 `wx` 验证聊天选择取消/大小限制、上传进度、返回页数、带授权下载、
  本地缓存上限与清理、晚到响应、会话切换、页面翻页/跳页/放大及单独重试预览。
- 项目自身的 WXML/WXSS 中无 `px` 尺寸；第三方 TDesign 包未修改。
- 微信开发者工具附带的 WXML/WXSS 编译器离线编译三个页面和全局样式通过。
- Windows 服务构建与 `CGO_ENABLED=0 GOOS=linux GOARCH=arm64` 构建通过。
- 更新本机测试服务，保留此前私有“本地调试（自动授权）”入口配置。

## 边界

上传、预览没有打印提交接口。HTTP 行为测试注入的 CUPS 读取器若被文档接口调用就失败；
本次检查和联调没有发出打印作业，也没有修改真实 CUPS 队列、驱动或打印设置。

源码和模拟 wx 的测试不等于微信运行时验收；离线编译不等于已看到模拟器画面。
以下仍待验证：

- 开发者工具实际选文件、图片显示、交互和不同屏幕布局。
- 手机从微信聊天选择 PDF、授权下载、放大、前后台恢复及网络中断。
- 普通用户正式扫码入口、request / uploadFile / downloadFile 域名与网络条件。
- 服务端在树莓派上的运行、工具可用性、中文字体及实际文件兼容性。
- 打印参数、CUPS 提交、实际出纸和手动双面；这些属于后续 M3/M4。

M2 文档属于上传时的会话；服务重启后原会话失效，需要重新扫码、选文件。
数据库持久化用于文档元数据和清理，不宣称已经实现跨会话恢复。
迁移和回退见 [数据升级说明](../migrations.md)。
