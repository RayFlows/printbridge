- 安装版本：`0.3.0-dev.20261014-rpi1`，Linux ARM64、CGO 关闭。
- 二进制 SHA-256：
  `4352e70a08fe7ed0f1dacf9a55bc6aff5cce417629989c863225770fa31ec5dc`。
  本机构建产物与设备文件校验一致。
- 配置、二进制和数据目录按 [部署说明](../deployment.md) 分离。
  `service.env` 为 `0600`；数据及配置目录为 `0700`。
- 用户服务已启用、运行，断开 SSH 后仍可访问；配置了失败重启。
  直接连接设备本机 CUPS，不再依赖 Windows 服务或 SSH CUPS 隧道。

## 已验证

1. 本机 `go vet ./...`、启用 Poppler 的 `go test -race ./...` 通过，结果命中既有测试缓存。
2. 交叉编译服务以及 `internal/pdf`、`internal/app` 测试程序后，实际在 ARM64 上运行。
   PDF 模块除明确跳过的 LibreOffice 测试外全部通过；app 模块全部通过。
   覆盖 Poppler 超时及错误、图片格式、EXIF 方向、真实 PDF 页序、缩放、边框及拼版。
3. ARM64 的虚拟 IPP 完整流程通过：正反阶段、倒序、补白、多份、拼版、
   长短边及不同背面顺序，包含翻纸等待和服务对象重建后的恢复。
   虚拟调度器只在内存中接收文件，不连接实体打印队列。
4. 树莓派正式服务通过存活、版本、未授权拒绝、会话授权、CUPS 列表和能力读取。
   Windows 主机也直接通过局域网完成存活、授权和打印机列表检查。
5. 在正式服务中上传八个合成夹具：三页 PDF、JPEG、PNG、WebP、BMP、
   两页 TIFF、GIF 首帧及带 EXIF 旋转的 JPEG。
   分页、首尾页原稿预览及最终排版预览通过，每个完整文件检查约 0.9–1.8 秒。
6. 三页手动双面倒序的准备结果为 `[3, blank]`、`[1, 2]`。
   替换未提交计划后旧计划被回收；没有提交打印任务。
   已目视检查设备生成的倒序首页及 JPEG 方向图。
7. 重启用户服务后，同一会话仍能读取文档和准备结果，预览 SHA-256 与重启前一致。
8. 重复安装同一版本成功；非法版本名和覆盖其他版本的安装被拒绝。
   Bash 语法检查和设备 `systemd-analyze --user verify` 通过。
9. 正式部署数据库为 schema 2，8 个文档、8 个计划、**0 个打印任务**。
   CUPS 历史作业总数保持 25，当前无活动作业。
10. Office 缺少转换器时上传 DOCX 返回 `503 office_unavailable`，没有伪造预览。
    依赖安装模拟只新增文档组件和字体，无 CUPS/驱动替换；安装脚本已准备但未执行。
