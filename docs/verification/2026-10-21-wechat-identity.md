# 微信身份、我的与机主管理验证

日期：2026-10-21。代码、隔离检查及正式部署通过；真实微信登录、机主指定、模拟器视觉和手机验收待完成。

## 故障复现与修正

先通过真实 HTTP 打印入口捕获 owner，在临时 SQLite 保存未完成任务，再重新授权。
原实现连续两次返回 HTTP 200、任务数 0：任务存在，新的 token 摘要却变成新的 owner。
修正后 owner 来自服务端已验证 `(AppID, OpenID)` 对应的稳定内部用户编号。

回归检查用模拟微信验证器、临时数据库及虚拟打印服务，不连接实体打印机：

- 同一人获得新令牌、关闭重开数据库后仍查到原任务，并能确认继续第二轮。
- 不同用户不能查看或继续该任务；不接受客户端提交的 OpenID、角色或任意用户编号。
- 服务装配使用合成登录适配器，实际执行登录、姓名、关闭服务、重开服务和角色配置；
  新旧令牌均能读取同一用户，且身份流程没有访问打印后端。
- 微信适配器验证固定 HTTPS 目标及参数，覆盖拒绝、限流、异常 JSON、重定向和网络失败。
  不把含 AppSecret 的传输错误或微信原始响应返回给客户端。

## 权限、姓名与迁移

- 首次姓名提示可跳过；跳过、编辑、清空及下次登录读取均经过真实 API/SQLite。
- 仅指定机主具有管理权限；普通用户和自报管理员字段不能提升权限，机主不能被封禁。
- 封禁立即拒绝旧令牌、新登录和翻纸继续；解封可恢复访问。
  封禁本身保留原任务，机主可另外确认取消，避免将权限变更和物理操作混为一谈。
- 新打印开关写入数据库；关闭后拒绝新计划和新任务，
  既有双面任务继续和幂等提交仍返回原任务。
- CUPS 查询失败明确报告设备状态不可用，不阻断用户管理、当前任务和服务开关。
- schema 1/2 顺序迁移、未来版本拒绝、重新打开、并发同 OpenID 登录、
  不同 AppID 隔离、用户及配置持久化检查通过；旧匿名 owner 没有被批量改写或自动认领。
