# 缺纸适配与弹窗验证

日期：2026-10-21。接续 [现场调查](2026-10-21-paper-out-investigation.md)。

## 已实现

- 可选 CUPS port monitor：原样转发打印流，同时消费 FD 3 的 Canon IVEC 回传。
  对完整、成功、明确的缺纸及恢复报文发出标准 CUPS 状态变化；重复报文不重复上报。
- 缺纸等待时有效重复报文延长监听；stdin EOF 后仍观察后端，先关闭 stdout 避免互相等待。
  取消中断阻塞输入、输出和回传。未知状态、坏 XML、静默超时或管道异常不清除缺纸。
- 任务页轮询同一打印机，缺纸弹窗每次事件一次，不调用打印或翻纸接口。
  页面隐藏、卸载、设备断开、终态和等待翻纸均不误弹；读取状态失败保留任务及提醒记忆。
- 删除任务页常驻“如果中途缺纸”提示。已有打印机页的一般状态说明保留原文。
- 独立安装和回退工具：空闲检查、拒收期间二次检查、PPD/监视器备份、
  不覆盖现有二进制、失败恢复及回退前的新配置检查。默认服务安装流程不变。


```text
/var/backups/printbridge-canon-monitor/Canon_G2810-0uh9rnkz/
```

安装改变 PPD 的监视器声明及选用，保留现有 Gutenprint 与 USB 后端程序。

## 取消收尾时的安装保护

正式安装发现：取消作业 30 后，Get-Jobs 已无未完成项，最初的 USB 后端却仍存活。
修改 PPD 时 CUPS 将该旧作业重新排入。日志明确记录
`Job restarted because the printer was modified.`，并保留原作业编号 30；
不是 PrintBridge 新建了另一任务。

已再次取消作业 30，并核实残留进程的可执行文件及 job-id 均属于该已取消的 USB 作业。
通过 pidfd 定向发送 SIGTERM，三秒仍未退出后发送 SIGKILL，确认退出；
没有重启整个 CUPS 或终止其他任务。一次性清理脚本已删除。

安装器原先只检查未完成任务列表，现同时读取 IPP `printer-state`；
处理中或未知状态拒绝安装/回退，空闲或停止且无任务才继续。
该检查仍在任何持久配置变更前及临时拒收后的第二次检查执行。

- 新增本地回归先失败、修复后通过；九项安装器检查全部通过。
- 树莓派独立 CUPS 中，用忽略 SIGTERM 的合成后端稳定复现：
  任务已取消并退出列表，但打印机仍处理中，旧安装器错误允许切换。
- 修复后在相同场景中拒绝切换、不生成备份或修改配置、不恢复旧任务；
  后端结束后，缺纸/恢复、打印流一致、重复安装和回退检查仍全部通过。
- 最后正式查询确认：作业 30 为 canceled，原残留 USB 后端已退出，
  队列空闲、接收任务、没有未完成作业，所选监视器保留。

此修正不改变监视器二进制、HTTP 接口或数据库。同期微信身份服务的部署另见
[微信身份验证](2026-10-21-wechat-identity.md)。
