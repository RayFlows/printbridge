# 自动预览与默认倒序验证

日期：2026-10-14。本地服务版本 `0.3.0-dev`，SQLite schema 2。
本记录取代此前移动端验证中要求手动“更新预览”和成功后自动回到顶部的交互。

## 当前行为

- 修改参数后立即使旧预览失效，停止修改 400 ms 后自动准备。
  准备期间可以继续编辑，布局和图片请求串行，仅最新设置的结果可以启用打印。
  卸载页面取消定时器并忽略迟到结果；预览失败显示重试图标。
- 正常更新不主动滚动。纸张安排保留占位，旧内容在失效期间隐藏，
  避免临时移除区域导致小屏页面在底部发生滚动夹取。
- 单面、手动双面和自动双面的新设置均默认整张纸倒序，用户仍可关闭。
  拼版小页和正反配对保持不变；奇数页的空白背面随其对应纸张移动。
  手动双面仍要求确认设备翻纸设置，默认倒序不代表完成了物理校准。
- 新计划成功后替换同一编辑过程的未提交计划；失败保留前一结果，
  已有打印任务引用的计划保留。详情与兼容策略见
  [ADR 0008](../decisions/0008-automatic-preview-and-sheet-order.md)。

## 自动检查

- `gofmt -l .` 无输出，`go vet ./...` 通过。
- 启用 `PRINTBRIDGE_TEST_POPPLER=1` 的 `go test -race ./...` 通过，
  包含真实 PDF、HTTP、SQLite 和仅监听回环地址的虚拟 IPP 调度器。
- TypeScript 类型检查、69 项客户端测试通过，五页 WXML/WXSS 编译通过；
  最终占位修正后重新执行客户端检查与设置页编译，均通过。
- Windows 服务重新构建并启动，沿用已有私有自动授权入口。
  本轮没有进行树莓派部署或物理打印。

客户端回归覆盖连续修改防抖、请求进行中继续编辑、过期成功和失败丢弃、
图片下载中参数变化、失败重试、输入中间无效值、离开页面及独立打印确认。
后端覆盖 1/2/3/16/17 页、非连续范围、拼版、多份、两种背面校准顺序。
连续 70 次替换保持一个计划和一个目录，另覆盖所有权边界、事务失败保留、
已有任务快照保留以及丢失响应后的重试。

实际 PDF 使用 `pdftotext` 逐面提取合成文档标记，独立核对准备文件及虚拟 IPP
收到的文件，而不是仅核对模型计算值：

| 三页文档场景 | 实际面序或阶段内容 |
| --- | --- |
| 单面倒序，两份 | 3、2、1、3、2、1 |
| 单面两页合一倒序 | 第一面含 3；第二面仍按 1、2 阅读 |
| 自动双面倒序 | 3、空白、1、2 |
| 手动长边倒序，两份，背面同序 | 正面 3、1、3、1；背面 空白、2、空白、2 |
| 手动短边倒序，两份，背面逆序 | 正面 3、1、3、1；背面 2、空白、2、空白 |
| 旧请求省略出纸顺序 | 保持 1/2、3/空白 的配对及原顺序 |

手动阶段检查包括等待翻纸、服务重启后继续及幂等提交。虚拟调度器还检查
CUPS 接收到 `page-set=all`、`output-order=normal`、`number-up=1`、`copies=1`，
避免对已排好顺序的文件再次筛选、倒序或拼版。没有使用真实打印队列执行这些测试。

## 实际模拟器

微信开发者工具 Stable v2.01.2510290、基础库 3.17.4、TDesign 1.17.0。
使用仓库三页合成 PDF 及超长中文测试文件名，不读取个人文档。

| 场景 | 结果 |
| --- | --- |
| iPhone XR，414×896 | 初始预览显示原稿第 3 页；修改份数自动生成新预览，完成后显示正确纸张总数 |
| 高级设置切换顺序 | 倒序开关默认开启；关闭/开启后纸张安排自动在 1、2、3 与 3、2、1 间切换 |
| 更新状态 | 生成期间“确认打印”禁用，设置仍可操作，没有手动更新按钮或自动回到顶部 |
| iPhone 5，320×568 | 文件名、预览、参数和固定底部操作可见，剩余选项可滚动访问 |
| 预览服务临时离线 | 修改份数后显示错误及重试图标，“确认打印”保持禁用；两行错误提示不遮挡重试按钮 |
| 恢复服务后重试 | 原页面直接恢复有效预览，份数保留，不必重新上传；未创建打印任务 |
| 最终占位修正 | 小屏参数区修改份数后自动恢复预览，纸张安排展开状态和当前参数位置保持 |

模拟器过程中只读查询本地 `print_jobs`，数量为 0。
既有 CUPS 连接仅用于能力读取，未修改队列或驱动，空纸盒未被用作测试隔离。
开发工具仍报告 TDesign 字体的 `ERR_CACHE_MISS`；已观察控件图标正常显示，
离线字体与实体手机效果没有据此判定通过。
