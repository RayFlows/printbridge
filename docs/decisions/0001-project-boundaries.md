# ADR 0001：独立项目、模块化服务和增量交付

日期：2026-10-13

状态：已接受

## 背景

目标是在微信内完成文档预览、打印设置和手动双面流程。
cups-web 的转换和 IPP 实现可供复用，但现有网页交互、临时转换接口和手动奇偶页操作
不能直接承担本项目完整流程。维护整套网页管理功能也超出了当前产品范围。

## 决定

- 使用独立仓库，同时维护小程序与 Go 服务。
- 服务初期为一个进程，按文档、打印流程、CUPS、访问和持久化划分代码职责。
- 选择性复用可验证的基础代码及成熟依赖，保留来源和许可；不整库导入 cups-web。
- HTTP 只做协议适配；页序计算和任务状态由服务端业务模块统一管理。
- 采用增量交付。M0 提供最小可运行工程，后续功能增量包含必要的微信端和服务端。
- 不提前发布独立 SDK，不预建插件框架、通用工作流引擎或大量空接口。

## 代价

本项目承担任务模型、设备交互和提取代码的维护责任。上游修复需要有选择地跟进，
不会因使用其部分代码自动获得。边界应由实际测试和变更约束保持，目录数量本身不代表解耦。

## 扩展与复议条件

新增客户端使用相同 API。新增文件类型进入文档准备流程。新增打印机差异通过
能力与校准资料表达。出现第二种实际后端或明确独立使用方时，再评估适配器扩展或拆库。
若后续评估发现大量底层代码必须整体同步上游，再复议 fork 方式并保留迁移记录。
