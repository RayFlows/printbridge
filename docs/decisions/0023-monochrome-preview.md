# ADR 0023：黑白预览与缓存兼容

日期：2026-10-22

## 原因

打印设置包含颜色模式，实际提交也向 CUPS 传递 `print-color-mode`，
但打印预览没有将模式传给栅格化器，黑白计划仍生成彩色 PNG。
旧计划已缓存的图片会在升级后继续掩盖修复。

## 决定

- `printing` 把不可变计划的颜色模式传给 PDF 适配器的打印预览入口。
  `monochrome`、`auto-monochrome` 使用 Poppler 灰度栅格化；
  `color`、`auto` 和缺省模式保留原色，不推测驱动的自动选择。
- 原始文档的预览入口保留原色。打印 PDF 及原始上传文件不为预览改写，
  实体输出仍由既有 CUPS 颜色选项处理，不叠加第二次 PDF 颜色变换。
- 打印预览缓存从 `page-N.png` 切换到 `page-color-v1-N.png`。
  新旧计划都绕过旧图片，按保存的颜色模式重新渲染。原有目录清理会一并回收两种缓存。
- 小程序沿用修改设置后自动准备、下载新计划预览的流程；不增加手动更新操作。

## 兼容与验证

HTTP 和持久化结构不变，无数据库迁移，不重排或重建已有任务。
原接口的预览行为说明同步到 OpenAPI。回退服务可忽略新版缓存；
已有取消保护等要求仍适用，不能因此回退到不支持当前任务状态的版本。

回归通过真实 PDF、Poppler 和模拟打印后端覆盖黑白、自动黑白、彩色、
自动及缺省模式的新计划和旧缓存，并检查重复读取、非空画面及零打印提交。
客户端验证彩色与黑白来回切换时，准备请求和下载图片属于同一设置快照。
自动检查纳入 CI，不依赖实体打印机；现场验证另见验证记录。
