# ADR 0016：微信持久身份与机主管理

日期：2026-10-21。状态：已实现代码；真实微信登录及正式设备启用单独验收。
首次姓名弹窗及扫码登录时机已由 [ADR 0017](0017-explicit-login-and-inline-profile.md) 调整；
稳定身份、权限与迁移的决定保留。

## 背景

原有文档和任务虽保存到 SQLite，owner 却是会话令牌 SHA-256。重新扫码生成新令牌，
因此编译/重新授权后，任务卡片查不到前一会话的任务。缓存不能代表一个人的身份。
产品需要自愿填写姓名、机主识别和封禁，以及小程序内的管理入口。

## 决定

- 微信侧调用 `wx.login`，服务端以自己的 AppID/AppSecret 调用 `code2Session`。
  `(AppID, OpenID)` 唯一对应一个持久化的随机内部用户编号；令牌只代表短期授权。
  不接受客户端传入 OpenID、角色或用户编号作为身份凭证。
- `accounts` 处理用户、姓名、封禁和新打印开关；`wechat` 只做微信登录适配。
  `pairing` 验证打印码、限流、签发会话和解析 owner；每个请求重新检查用户是否被封禁。
  文档和打印业务继续只接收 owner，不依赖微信 API。
- `management` 聚合打印机与未完成任务，并在业务入口检查管理员身份。
  HTTP 只做协议映射，不直接读写 SQLite 或调用 CUPS 命令。
- 管理员由私有服务配置的 `PRINTBRIDGE_ADMIN_USER_ID` 指定唯一用户。
  初次登录者不会自动成为管理员，姓名也不能授予权限；用户可在“我的”复制自己的编号。
- 姓名由用户自行提供，最多 40 个 Unicode 字符，不做真实身份认证。
  首次提示可跳过；跳过、编辑和清空都保存到服务端。姓名仅供机主识别使用者。
- 底栏为“打印 / 我的”；管理入口仅在当前服务端返回管理员角色时显示，
  服务器仍独立校验每个管理请求。
- 机主可查看用户、封禁/解封、设备与未完成任务，并暂停新计划和新任务；
  继续/取消既有任务不受全局新打印开关影响，幂等重试仍返回原任务。
  上传本身不提交打印，关闭开关后尚未打印的文件仍按文档 TTL 回收。
  管理员可单独确认取消遗留任务，不能借此浏览他人的文档内容。
  CUPS 查询失败单独报告设备状态不可用，不阻断用户管理或服务开关。
- 封禁阻止旧/新会话访问，不在封禁时顺带修改已提交的物理作业；
  如需取消，管理员在看板进行独立操作。

## 兼容与迁移

schema 3 增加用户、会话 user_id 和新打印开关，不重写旧文档/计划/任务 owner。
已配置微信凭据的服务拒绝匿名会话和仅打印码登录；不提供静默回退。
未配置凭据时保留原匿名模式以便旧部署升级，元信息不返回 `loginMode=wechat`，
“我的”明确显示尚未启用身份登录；此模式不解决跨会话恢复。

旧匿名任务不能推断属于哪位微信用户，不分配给第一位登录者，也不按姓名认领。
管理员看板仍能看见遗留任务并确认取消。更换 AppID 后旧应用用户不可继续访问。
数据库降级必须恢复升级前的完整数据及匹配二进制，不提供修改版本号的伪降级。

AppSecret、session_key、登录临时代码、原始 OpenID 不发送到客户端或记录在日志。
SQLite 保存 OpenID 用于唯一映射，用户资料不随打印文件三天清理，避免封禁/身份失效；
姓名可以清空。部署者必须单独管理账号数据及备份的保护、保留和删除请求。
微信后台隐私指引应如实说明自行填写的姓名及用途，主体和审核结果不得由代码测试推定。
