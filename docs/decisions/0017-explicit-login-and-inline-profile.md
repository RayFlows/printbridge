# ADR 0017：微信原生隐私授权与姓名页内编辑

日期：2026-10-21。状态：代码及本地检查通过；微信运行时与手机验收待完成。

## 背景

用户要求在授权弹窗点击同意，不再弹出首次姓名提示，在“我的”自愿填写姓名，
并将退出入口统一放在“我的”。随后明确用户从微信“扫一扫”进入，要求复用现成授权界面。
因此删除此前多加的整页登录按钮，直接使用微信官方原生隐私弹窗，
不再另画一个底部授权弹层。这调整 ADR 0004 的会话申请前置条件及 ADR 0016 的姓名弹窗。
扫码仍携带所需连接信息，不恢复地址、配对码表单或二次扫码步骤。

## 平台依据

2026-10-21 读取微信官方文档：

- [wx.login](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/login/wx.login.html)
  描述获取一次性登录 code，再由服务端换取身份。普通小程序的该页没有要求每次调用
  必须由用户点击触发；其中插件授权条件不能泛化到普通小程序。
- [小程序隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)
  将隐私接口调用前的用户同意与登录 code 分开说明；要求后台如实配置隐私指引。
  指南说明 `wx.requirePrivacyAuthorize` 可以触发隐私确认，开发者未响应自定义事件时，
  微信提供官方弹窗；隐私接口自基础库 2.32.3 起支持。

因此用户在需要时点击微信原生隐私弹窗的同意按钮，不增加另外一层登录按钮。
不将 `wx.login` 描述为读取微信头像、昵称、姓名或手机号的用户资料授权，
也不以接入原生弹窗推定已经通过微信审核。

## 决定

- 扫码及外部入口解析并暂存目标后，先等待 `services/privacy` 的隐私确认，
  再调用既有会话服务获取 code 和申请会话。
  使用官方隐私弹窗与官方隐私指引页面，不注册自定义同意处理，
  不自行绘制授权弹层或缓存同意状态。是否需要弹窗由微信决定，
  不承诺原生弹窗固定为底部样式，已记录有效同意时不强制重复操作。
- 保留 `pages/connect/index` 路径兼容已生成小程序码，但不将它作为额外登录或扫码步骤。
  有目标时只显示加载、错误和重试；没有目标、没有有效会话的直接打开才显示扫码入口。
- 拒绝同意或缺少隐私 API 时停止，不匿名回退。重试沿用内存中的目标；
  连点不重复提交。隐私确认期间离页或新扫码使旧操作失效，
  已签发但过期的异步会话继续按已有规则撤销。
- 有效会话的普通重入继续恢复打印机页。新扫码依然优先于旧缓存，取消更换保留旧会话。
- 姓名仅在“我的”页内自愿输入、保存和清空。输入本身不保存，
  首次打印页只读账号/打印开关，不自动写空姓名。保存失败保留草稿，可再次点击保存；
  新账号或已隐藏页面不接收旧资料响应。
- 保留 API 的 `namePrompted` 字段及旧数据，不再据此驱动姓名提示，无新增迁移。
- 退出仅保留在“我的”，含服务离线时的本机退出；退出会话不删除账号。
- 显示名改为“打印账户编号”。其值继续使用服务端加密随机生成的 16 字节内部 ID，
  不是 OpenID，也不由 OpenID 截断或编码得到。OpenID、AppID 和会话密钥不返回用户或管理 API。

## 验证与边界

TypeScript、133 项客户端检查、三个页面及全局样式的官方离线编译通过；
Go vet/race 通过，新增响应检查覆盖登录、读写个人资料、管理列表及封禁。
自动检查使用模拟微信、临时数据库及虚拟后端，没有操作实体打印。

本轮不改变服务端运行逻辑、API 契约、数据库版本或正式部署。
需要在微信后台完善实际隐私指引，并分别验证原生弹窗的拒绝/同意、再次进入、真实登录、
页内姓名、仅“我的”退出以及手机布局。离线编译和模拟接口不证明真机或审核通过。
