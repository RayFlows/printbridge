# ADR 0024：隔离访客网与同网段扫码入口

日期：2026-10-22

## 背景

访客需要使用微信打印并保留互联网连接，不能进入机主主网；机主继续从自己的 Wi-Fi 打印。
微信局域网 HTTP 规则要求目标 IP 与手机处于同一网段，单纯放行跨网段路由不足以满足条件。
现场 Kwrt 已有上网认证脚本、IPv6 relay 和主网硬件加速，不能为打印整体替换网络配置。

## 决定

- 独立 SSID、桥接设备、IPv4 子网、DHCP 和拒绝默认策略。访客仅允许 DNS、DHCP、
  IPv4 上网及一个限定源网区、目标地址和端口的打印入口。
- 访客网关的打印端口 DNAT 至主网 PrintBridge；不开放 SSH、CUPS、路由器后台、
  主网互访或 WAN 打印映射。启用 AP 和桥端口隔离；访客不分配或转发 IPv6。
  主网的 IPv6 配置保持原值。
- 全体访客共用互联网下行 20 Mbps、上行 5 Mbps。现场缺少可用 tc/调度模块，
  软件源也已失效，因此采用 nftables 字节速率限制，超额丢包，不把它描述成 SQM。
  打印入口的局域网流量不计入互联网限额。
- 保留主网 flow offload。fw4 的普通 chain-pre 扩展在 flow-add 之后，
  因而使用 table-pre 定义访客检查链，再以 ruleset-post 的 `insert rule` 在同一
  nft 事务中将入口放到 forward 首条。访客两个方向都在该链中终结，不进入 flow-add。
  其他流量返回原链；不修改 fw4 自身、原上网脚本或已有主网配置项。
- 打印码 v2 增加可选 `alternateServers`，最多三个备用地址；旧单地址码保持原行为。
  多地址码的全部地址必须是互不重复的私有 IPv4 origin，不允许域名、公网、
  回环、链路本地地址、路径或凭据。
- 隐私同意后，小程序使用 `wx.getLocalIPAddress` 的地址与真实子网掩码选择唯一同网段入口。
  API 不可用、超时、掩码缺失、网段不匹配或有多个匹配时明确失败，不探测地址或试发授权。
  进入新扫码或离开页面后，旧地址查询不得继续登录。
- 仅在扫码授权时选择地址；已保存会话继续绑定原 origin，不将现有令牌自动转发到另一个地址。
  切换 Wi-Fi 后重新扫码，服务端仍通过已验证微信身份恢复自己的任务。

## 兼容与维护

不修改 HTTP API、数据库、CUPS 队列或打印配置。新客户端兼容旧码；
旧客户端会拒绝含新字段的码，部署顺序是先更新小程序，再重新生成打印码。
生成工具增加可重复的 `--alternate-server` 参数，仍校验微信 path 长度上限。
开发启动项是私有配置，不把配对码或 Wi-Fi 密钥纳入仓库。

开发工具模拟扫码使用单入口启动参数，不加入 `alternateServers`。
现场有线电脑的模拟器返回虚拟网卡地址且缺少掩码，无法用于判断主网路由。
模拟器明确连接部署者指定的可达地址，沿用单入口协议；手机多入口选择仍需真机验收。
不为此猜测掩码、关闭电脑虚拟网卡或放宽手机入口校验。

网络变更先备份、证明原配置项未变、检查 nft 规则，再开启自动回滚保护并增量重载。
确认后取消回滚，不在验证过程中重启路由器、重装固件或强装内核模块。
若以后启用透明代理、改变 WAN 设备或升级 fw4，重新检查隔离、规则顺序及限速，
不能仅凭 UCI 项仍存在认定生效。现场验证及剩余边界见
[访客网记录](../verification/2026-10-22-guest-network.md)。

- `https://developers.weixin.qq.com/miniprogram/dev/framework/ability/mDNS.html`
