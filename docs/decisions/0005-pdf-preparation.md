# ADR 0005：独立文档生命周期与原生分页预览

日期：2026-10-14

状态：已采用

## 背景

M2 需要贯通微信聊天选 PDF、上传、页数和翻页放大。后续打印、拼版和手动双面必须围绕
同一份已准备的文档扩展，不能在预览时提前打印，也不能把业务绑定到网页 PDF.js。

## 决定

- `documents` 负责文档生命周期、所有权、文件、过期和分页缓存，只依赖 `Repository`
  与 `Processor` 两个实际可替换接口。没有 CUPS、HTTP 或微信依赖。
- `store` 使用固定版本的纯 Go SQLite 驱动，保留无 CGO 的 ARM64 构建。
  元数据通过编号 SQL 迁移，源码 PDF 与分页图放在独立的数据目录。
- `pdf` 用无 shell 的独立进程调用 Poppler `pdfinfo` / `pdftoppm`。原始 PDF 在 M2
  就是准备结果；不做页码抽取、缩放或单双面过滤。后续打印模块只增加明确版本的页面安排。
- 上传同步完成页数校验，成功后才提交文档元数据。单页图按需渲染，经 PNG 校验后原子改名。
  失败不返回可用文档或半张图片。一次只运行一个文档处理操作，忙时明确返回可重试错误。
- 固定首版资源上限：20 MiB / 500 页、最多 64 份文档、文件总量 512 MiB。
  单页图最长边 1600 像素、最多 12 MiB；生成中的单页临时文件可短暂增加磁盘使用。
  HTTP multipart 临时文件另外最多一份，有总请求体限制。工具默认超时 30 秒。
- 文档属于上传会话，数据库只保存令牌的 SHA-256 摘要；其他会话得到 404。
  HTTP 所有预览请求都检查会话，即使命中缓存。授权信息不出现在图片 URL 中。
- 沿用 M1 的易失会话。因此重启或重新扫码后的会话不能恢复旧文档，需要重新选择文件；
  旧文档到期后回收。M2 不提供跨会话收件箱。M3 的持久任务归属与恢复需要另作决策。
- 默认 24 小时到期。启动、上传前和每分钟清理到期文档及无元数据的中断上传目录；
  与上传、渲染共用互斥入口，不能删除进行中的文档。应用关闭时停止清理并关闭数据库。
- 客户端 `DocumentSession` 绑定一次授权和一个页面，处理聊天选取后的上传、带授权下载、
  错误与最多六张本地分页图缓存。离开页面会中止上传/下载并释放临时图片。
  页面只组织状态，不计算打印页序。回到前台、放大前重新确认文档可访问。

## 界面与来源

参考 cups-web 固定提交 `b2a3082b635b7fd2abd0e5efadfdd69609200e52` 的
`frontend/src/components/print/FileUpload.vue`、`PrintPreview.vue`、`PdfCanvas.vue`：
紧凑的文件信息、独立预览区域、翻页和放大。未复制 Vue、PDF.js 或其他上游实现。
以原生 WXML / WXSS / TypeScript 和现有 TDesign 重写，项目界面尺寸使用 rpx，
比例与视口上限使用百分比 / vh，保持 PDF 原页方向。

M2 不展示尚不能工作的纸张、份数和提交打印控件。M3 将在同一文档流程中贯通参数与真实任务。

## 代价与验证

运行设备额外需要 Poppler。缺失工具明确失败，但不影响服务启动、扫码及读取打印机。
工具进程有时间、并发、输出和输入限制；这些不等于操作系统级隔离或进程内存硬限额。
当前仍是可信局域网部署范围，不把它描述为公网多租户文档处理服务。
自动检查使用模拟工具、临时数据库和合成 PDF；真实 Poppler 检查需显式启用。
M2 没有打印提交接口，任何检查都不以空纸盒作为隔离。
