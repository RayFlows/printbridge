# ADR 0013：卡片内恢复任务与文件保留期限

日期：2026-10-21

## 原因

普通用户一次处理一份文件，独立“打印任务 / 全部任务”列表增加了返回路径。
打印机详情应通过信息图标进入独立页面，未完成任务应在打印机卡片内直接可见。
历史记录用于恢复、幂等和排障，不应要求长期保存可下载、可重印的文档。

## 决定

- 打印机卡片的 `i` 图标打开 `printer-info` 页，移除详情下拉。
  当前授权在该打印机有未完成任务时，卡片下方显示文件名、纸张数和状态，
  主操作改为“继续任务”；结束后恢复“选择文件”。
- 移除小程序历史入口。无任务编号的旧任务页入口返回打印机页。
  `GET /jobs?active=true` 只返回当前会话的未完成任务，省略参数保留旧列表契约。
  旧部署积累多个任务时，卡片优先打开最早的未完成任务，不丢弃已有队列。
- 服务端在保留同一幂等键重试语义后，拒绝同一会话在同一打印机的新任务，
  返回 `409 active_print_exists`。不同会话或不同打印机仍使用原有调度。
  它不提供跨会话认领，也不锁住来自其他 CUPS 客户端的作业。
- 终态任务的阶段文件在下一次成功清理时回收，正常周期为一分钟。
  没有其他活动任务引用同一文档时，同属会话的原文件、转换结果、预览与相关计划一并回收。
  未提交的文档默认上传后 24 小时过期，计划仍为准备后 24 小时过期。
- 终态任务元数据与幂等键保留 3 天，按最后状态更新时间计算。
  活动任务按创建时间满 3 天进入取消流程，不能因为后台轮询刷新时间而永远保留。
  尚未提交或等待翻纸的任务可本地取消；已提交或提交结果不确定的任务必须核对 CUPS，
  确认终态前保留恢复文件和打印机占用。不能声称所有文件都有绝对 3 天的删除保证。
- 中途缺纸保留原任务并按打印机面板提示恢复，不重复提交文件。
  小程序“继续打印另一面”只用于翻纸确认，不是缺纸恢复或 CUPS 队列恢复按钮。
  未验证的设备缺纸反馈不包装成已支持的远程控制。

## 兼容与运维

数据库仍为 schema 2，不增加 SQL 迁移。新查询参数和错误码同步记录在 OpenAPI。
本决策替代 ADR 0006 的终态文件 24 小时、元数据 7 天及活动任务无限保留策略；
也收紧 ADR 0012 中未限定的同会话任务提交行为。

升级先确认没有活动任务并备份完整数据。新清理策略会回收旧终态文件和超过 3 天的记录；
回退旧二进制不会恢复已清理文件。备份同样包含文档，部署者应按保留要求处理备份，
不能将升级备份描述为已删除的用户文件。

CUPS 自己的 spool 文件和任务历史独立配置，本服务不更改 CUPS、驱动或队列。
尚未核对该层的实际保留期限，不能宣称 PrintBridge 清理等于整机全部副本删除。

## 验证边界

自动检查使用模拟 `wx`、临时目录、SQLite、模拟或虚拟 IPP。
微信模拟器、ARM64 服务和真实缺纸续打分别验收；不因打印机空纸盒而向实体队列提交测试。
