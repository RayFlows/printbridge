# ADR 0020：取消核对与打印机缓存

日期：2026-10-21

后续：设备清理及人工确认部分由 [ADR 0021](0021-verified-usb-cancellation.md) 更新。
队列保护、持久化和后端释放核对仍保留。

## 原因

缺纸后在小程序取消任务，再补纸或提交新任务，可能输出旧页。
现场作业 34 的 CUPS 取消与 USB 后端退出相差 62 秒；作业 35 也在取消后保留后端。
IPP 的终态不代表后端退出，也不证明打印机内部缓存已清空。
现有驱动没有经过验证的设备取消接口，不能把 Cancel-Job 宣称为清空打印机。

## 决定

- `printing` 继续负责同一打印机的任务串行化。新任务创建 CUPS 作业及释放 held 作业前，
  必须确认队列为 idle；processing、stopped、断开、缺失和未知状态均不视为空闲。
- 已提交任务取消后先核对任务名称、CUPS 终态和队列空闲，保留 `canceling` 和原任务文件，
  阻止同一打印机的后续任务发送。外部取消和异常终止也走同样的保护。
  调度先恢复已有占位，再处理 queued 任务；旧积压任务或时钟变化不能抢在取消确认之前。
- 可能已经发送到设备的任务增加可选 `deviceCancelRequired` 标志，存入现有任务 JSON，
  不新增数据库表或破坏性迁移。应用重启、客户端重入和三天过期不绕过保护。
- 队列空闲仍不能证明设备缓存为空。因此用户先按打印机停止键，再在任务页确认。
  服务端在确认时重新检查归属、任务名称、CUPS 终态和设备队列状态，不能信任旧页面结果。
  管理员可在看板为原用户确认；普通用户无法操作其他人的任务。
- 新增用户和管理员 `confirm-cancel` 接口，必须提交 `deviceStopped=true`。
  重复确认终态任务保持幂等；确认不发送打印数据、不重发旧任务、不重置 USB。
- 从未提交的 queued 任务及 awaiting_flip 任务维持直接取消。
  未提交成功的空 CUPS 作业可以自动结束，但也要等后端释放设备。

## 兼容与边界

API 为现有 v1 增加可选字段、问题值和操作。旧数据缺省为 false，读取活动任务时按其
实际 CUPS 状态核对；旧终态记录不会自动复活。
服务端与小程序应同时升级，旧客户端不能完成新增加的设备停止确认。
回退前先清空未完成任务；旧版本不认识保护标志，不能在取消尚未完成时直接回退运行。

此流程依赖用户真实执行面板停止操作，不宣称能够远程验证缓存清空。
队列 idle 仅是 CUPS 后端释放的证据，不是实体纸张完成证明。
不修改驱动、monitor、PPD、队列设置，不杀进程，也不控制外部 CUPS 客户端的提交。
其他客户端仍可能直接向队列打印；本服务不能承诺全局独占。
对仍未退出的后端不设置“超时成功”，持续显示等待，交由管理员核对。

复现、隔离设备和现场证据见 [取消验证](../verification/2026-10-21-cancellation.md)。
