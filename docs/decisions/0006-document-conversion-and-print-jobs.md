# ADR 0006：统一文档转换与持久化打印流程

日期：2026-10-14。状态：已采纳，硬件验收独立进行。

用户要求完整的微信打印流程。PDF 是内部交换格式，不是可选文件的产品边界。
聊天文件和照片先进入 `documents`，`pdf.Prepare` 将支持的格式转换为 PDF；
Office 使用独立进程 LibreOffice，图片和布局使用固定版本 pdfcpu，JPEG 方向使用 imaging。
原文件、转换结果分开保存。未知格式、加密、转换失败和缺少工具明确报错。
GIF 只打印首帧，TIFF 保留多个图像页。

`printing` 唯一负责范围、奇偶、倒序、拼版、补空白、份数和手动双面的页面安排。
先生成不可变 Plan，预览其最终纸面；Job 固定该 Plan 并制作正背面文件。
之后修改页面上的设置不改变已有 Plan 或 Job。预览不创建 CUPS 作业。
手动背面的设备旋转和输出顺序只在阶段文件中应用，预览显示正常阅读方向；
纸张安排显示原始页码，空白为 0。

CUPS 适配器使用 Create-Job（indefinite hold）、Send-Document、Release-Job。
任务状态、稳定作业名及 CUPS ID 在副作用前后持久化；发送前确认 hold，
发送响应丢失时核对 number-of-documents，不盲目重发。
未能可靠核对时保留 `submission_uncertain`，允许请求取消并持续核对。
不存在可靠通用的“恰好打印一次”硬件保证，本方案优先避免自动重复出纸。
适配器覆盖 page-set=all、copies=1、number-up=1、output-order=normal，
不再附加原文档范围或奇偶过滤。

PrintBridge 只串行化自己对同一队列的任务；外部 CUPS 客户端仍可插入。
CUPS 的 completed 仅表示调度器报告完成。手动双面必须由用户确认纸张全部输出、
按校准方向重新放入后继续背面。客户端保存对应服务/队列的顺序与额外旋转设置，
任务快照也保留它们。该设置来自用户确认，不等于本项目已实测 G2810。

schema 2 保存 Plan、Job 和会话哈希。保留 M1 的交换与撤销 API，
会话有效期内重启可恢复文档和任务；更换访问码撤销旧会话。
原始令牌不落库。终态文件 24 小时回收，任务与幂等记录保留 7 天，
活动任务持续保留以便核对；超期或失去会话的活动任务需部署者处理，
不能不核对 CUPS 就删除它们并释放打印机。

尚未实现多用户账户、跨会话认领任务、全局 CUPS 独占或自动设备校准。
这些不是当前 UI 已完成的能力，也不通过空接口预建。
