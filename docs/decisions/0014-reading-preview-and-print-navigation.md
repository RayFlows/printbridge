# ADR 0014：阅读顺序预览与打印副本中的导航信息

日期：2026-10-21

## 原因

用户预览需要先看到第一页，逆序出纸和手动双面阶段是设备执行细节。
三页双面计划为配对补出的第四面不应成为阅读预览的最后一页。
设置页的纸张安排列表重复暴露机器页序，普通用户只需要预览、设置及翻纸图示。

带分层命名目标的 PDF 在 pdfcpu v0.16.2 排版后，导航信息仍可能引用旧页面对象。
之后倒序或抽取阶段文件会在迁移、删除命名目标时失败。原稿可正常渲染，
关闭优化也不能修复；合成分层目标树可复现，与个人文档内容无关。

## 决定

- 打印仍以同一份排版 PDF 为准，保留现有整张纸倒序和手动双面两轮页序。
- `printing` 根据已有页面安排，将阅读索引映射到实际排版面，不在客户端另算页序。
  阅读顺序指页码选择和拼版后的顺序、应用 `outputOrder` 之前；保留每面内的拼版顺序。
- 分页接口增加可选 `order=reading`。省略或 `print` 保持旧版物理页序。
  新增可选 `previewPageCount`，仅排除软件为双面配对补出的最后空白面；
  原稿自身的空白页及拼版的空白格仍保留。
- 老计划读取和相同参数复用时由已存参数计算预览面数，不重写 PDF、不迁移数据库。
  服务端缓存按实际排版面共享；客户端缓存区分两种预览顺序。
- 小程序设置页使用阅读顺序，移除“纸张安排”及其状态、事件和样式；
  保留总纸张数、份数和翻纸示意。
- PDF 适配器在首次选择打印页面时，使用 pdfcpu 的结构化上下文 API，
  从内存中的迁移缓存移除命名目标，再抽取到新的打印上下文。
  不递归删除导航对象，避免误删页面共享对象。新的上下文不继承原目录和打开动作。
  只处理打印副本，不修改原文件、正文、图片或原稿预览，不进行整页栅格化。

## 兼容和回退

数据库仍为 schema 2。新字段可选，旧客户端仍使用原来的分页语义。
本决策替代 ADR 0006、0008 中将普通用户预览及纸张安排列表按物理页序显示的部分。
小程序和服务端一起升级才能获得阅读预览；旧服务端没有该功能。
回退旧服务端后，新字段可能留在 JSON 记录中，Go 读取会忽略它，不改变打印流程。
已生成的旧计划及任务不在升级时自动重建。先前失败、未保存的计划可直接重试。

本决策使用已固定的 pdfcpu v0.16.2 公共 API，没有复制第三方实现。
更换 PDF 库或版本时应保留分层命名目标、内容像素和后续阶段抽取的回归检查。

## 验证边界

以合成文件检查命名目标、原件未改动、倒序、旋转、多份及内容颜色；
以临时目录和虚拟 IPP 检查阅读索引、缓存、双面空白和打印页序。
用户原稿在树莓派上只做排版和预览验证，不提交实体打印。
