# ADR 0008：自动预览与整张纸倒序

日期：2026-10-14

## 原因

修改参数后要求手动更新预览打断打印设置流程。预览自动生成还会更快达到原有的
64 个计划上限。用户的出纸堆叠方式需要默认从最后一张纸打印，简单反转原稿页码
却会交换双面正反、破坏拼版小页顺序，并把奇数页文档的空白面放到错误位置。

## 决定

- 小程序设置变化立即使旧预览失效，400 ms 防抖后自动准备。布局与图片请求串行，
  正在生成时允许继续编辑，仅最新设置结果可以启用打印。正常更新不改变滚动位置。
  失败可以重试，打印仍必须独立确认，准备及预览不得创建打印任务。
- `printing` 先完成选页、拼版、补空白与正反配对，再按 `outputOrder` 排整张纸；
  PDF 适配器执行业务层给出的面序。纸张安排、预览和打印引用同一个有序 PDF。
  手动双面的 `backOrder` 只表示重新进纸时背面相对正面的校准顺序，不能和整份倒序混用。
- 小程序新设置默认 `outputOrder=reverse`，单面、手动双面及自动双面均保留此选择。
  例如 16 页双面从 15/16 这张开始，最后打印 1/2 这张，而不是将 16 与 1 配对。
- 准备请求可携带 `replacesPlanId`。同属一个会话、同一文档且尚未被任务引用的前一
  计划在新计划保存成功时被替换；数据库写入/移除在一个事务完成，文件在提交后清理。
  失败保留前一计划，孤立目录由已有清理过程回收，已提交的任务快照不被替换。
  相同且未过期的前一计划可以复用；不存在的前一编号允许重试，以容忍丢失响应。

## 兼容性

`outputOrder` 和 `replacesPlanId` 都是可选字段。旧请求省略 `outputOrder` 保持原顺序；
旧 `reverse` 仍表示拼版前的原稿页码反转，不更改其含义。新小程序保持 `reverse=false`。
不修改 CUPS 队列默认，不把倒序再次作为 CUPS 过滤参数提交。
SQLite schema 仍为 2，无数据库迁移，也不重写已有计划或打印任务。

## 验证边界

验证包括防抖/请求交错/失败/卸载、计划替换事务与所有权，以及真实 PDF 和虚拟 IPP
接收的正反面内容。G2810 的物理翻纸顺序仍需纸张实测，不能由默认倒序推断。
