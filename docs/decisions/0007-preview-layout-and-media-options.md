# ADR 0007：移动端预览及设备、排版选项

日期：2026-10-14

后续 [ADR 0008](0008-automatic-preview-and-sheet-order.md) 将修改参数后的预览改为自动更新，
独立确认打印的边界保持不变。

## 原因

真实微信模拟器中，原生按钮的默认宽度覆盖了预期布局。
两个仅含图标的按钮各占约 160.5 屏幕像素，文件名的 flex 区域被压至 0。
离线 WXML/WXSS 编译和业务模拟测试都不能发现此类运行时样式问题。
原有设置页把最终预览放在全部表单之后，手机需要反复滚动才能确认。

## 决定

- 自有样式使用 rpx，TDesign 通过其 `custom-style` 明确图标/整行按钮宽度。
  原生整行按钮明确设置宽度，不改第三方运行包源码。
- 上传后进入同一预览及设置页。初始准备默认预览；修改参数立即使原计划失效；
  重新预览与最终确认打印保持不同动作，准备绝不创建打印任务。
- 纸张类型、进纸位置来自 CUPS 能力并由业务层校验。未知能力只用队列默认，
  不将其他型号的列表硬编码为当前设备可用能力。
- PDF 适配器使用 pdfcpu 先把选定的每页归一到独立小页画布，再执行拼版。
  放大内容在小页边界裁切，不能越过相邻小页。预览和打印共用结果。
- 页选择和手动双面阶段仍归 `printing`。拼版顺序仅改变小页位置，
  不再向 CUPS 发送奇偶、缩放、拼版顺序或边框过滤指令。

## 兼容性及验证

新增 `mediaType`、`mediaSource`、`layoutOrder`、`pageBorder`、`scaling` 为可选字段。
缺失或空 `scaling` 保持旧版相对适应布局缩放的行为；显式 `custom`
表示原稿物理尺寸的百分比。旧打印任务快照和已准备 PDF 不重写，无数据库迁移。

验证分别包括接口/模拟 IPP、真实 PDF 栅格像素、小程序行为及真实模拟器画面。
手机、树莓派服务运行和物理出纸仍需独立验收。
