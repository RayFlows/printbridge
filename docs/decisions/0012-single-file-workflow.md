# ADR 0012：单文件编辑与原地重新上传

日期：2026-10-20

## 原因

上传自动打开设置页，却用入栈跳转保留了原来的文档预览页。设置页的文件按钮只替换
栈顶页面，再次上传又压入设置页，反复操作会残留多层旧文件。两页预览及打印入口
也不符合一次上传、一次确认打印的交互；手动双面尤其不需要多文件批量入口。

## 决定

- `document` 页只承担首次选择和上传。成功后用 `redirectTo` 替换为设置页，
  不下载原稿预览，不保留独立预览或“设置打印”按钮。设置页返回直接回打印机列表。
- `settings` 页拥有唯一的预览、参数及打印确认；右上角显示“重新上传”。
  该动作在原页选择聊天文件或相册图片，不创建另一个文件选择页面。
- 替换上传使用独立的 `DocumentSession`，上传成功后才切换当前文档及会话对象，
  并释放旧预览缓存和下载任务。取消、选取失败或上传失败保留原文件、设置和预览。
- 新文件恢复全部默认打印参数与控件索引，页码、份数、单双面、效果等不隐式继承。
  不同文档不共享 `replacesPlanId`；旧文档的准备结果与图片不能覆盖新文档。
- 选取和上传期间禁止再次替换、修改参数及确认打印。离开页面中止传输并忽略晚返回结果。
  新文档上传成功但预览失败时保留新文档，仅重试准备或下载，不重复上传。
- 保留服务端任务历史、调度、幂等提交和手动双面保护。不增加全局单任务限制，
  不改变原文档的到期回收策略，不将上传或预览视为打印提交。

## 兼容与验证

HTTP、数据库、服务端页序和设备配置不变，无迁移或服务端升级要求。
原始文档分页接口仍供其他客户端使用，只移除小程序中的冗余原稿预览页面。

回归测试运行真实页面处理器和服务层，以模拟导航栈覆盖首次上传、返回、连续十二次
替换、取消及失败。另覆盖上传/预览/准备交错、双击、卸载和授权过期，断言全过程不
请求打印任务接口。离线模板编译及模拟 `wx` 检查不能替代微信模拟器和手机验收。
