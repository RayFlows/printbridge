# ADR 0004：扫码自动进入打印流程

日期：2026-10-14。状态：采纳，取代 ADR 0002 的地址二维码及手工配对交互。

## 问题

用户要求微信扫码后直接进入打印流程。原实现只用扫码填地址，仍需输入配对码并点击连接，
把部署和授权的实现细节交给普通用户，也不能处理从微信外部入口直接进入的参数。

## 决策

保留现有服务端会话接口，改变凭据的交付和客户端交互。二维码携带服务地址和专用打印访问码，
扫码后客户端检查服务类型及 API 版本，自动用码内凭据换取有限期会话，再打开打印机页。
M1 只显示真实队列和能力，M2 再接入文件选择；不增加尚不可用的上传或打印按钮。

二维码 v2 的 JSON 契约为：

```json
{"type":"printbridge","version":2,"server":"http://printbridge.example.test:8080","pairingCode":"test-only-pairing-code-0123456789012345"}
```

`server` 必须是可规范化的 HTTP(S) origin，`pairingCode` 沿用服务端 32 至 128 位无空格
可打印 ASCII 约束，不接受其他字段。该码是可重复扫描的打印访问凭据，不是管理员密码、
CUPS 密码或微信 AppSecret。它授权访问当前 PrintBridge 服务，不代表仅限某一个 CUPS 队列。
可选的按打印机限制应在业务确实需要时加入服务端校验，不能只在界面隐藏队列。

正式入口采用微信 `getwxacode`，路径为 `pages/connect/index?entry=<百分号编码的 v2 JSON>`。
接口支持最长 1024 字符的 path 和 release/trial/develop 环境；生成工具验证路径长度。
选择可直接携带路径的接口，不为当前少量自托管设备引入短码目录服务器。
没有短码解析服务，当前不支持 `getwxacodeunlimit` 的 scene 短码。

生成工具仅在部署者的 Node 环境运行。服务访问码与微信 access token 从环境变量读取，
图片存入默认被忽略的 `data/`，错误只包含本地固定消息和微信错误编号；
不打印完整入口路径、凭据、微信返回的原始错误详情，也不把 token 放进小程序包。
工具不管理 AppSecret、刷新微信 token 或替用户发布小程序。

从微信入口进入时自动使用 query；应用已在后台运行时，`App.onShow` 也接收新的入口。
同一次入口的普通前后台切换不重复授权；微信的 `scancode_time` 用来区分再次扫码。
直接打开小程序而没有新入口参数时，恢复已有会话，或者显示扫码按钮。
小程序内 `wx.scanCode` 支持当前小程序码返回的 path，并保留 v2 JSON 普通二维码供局部调试；
普通 JSON 二维码不等于能从微信外部打开小程序的入口码。

解析、请求和会话在 `services/`，页面只持有加载、失败和重试状态。打印访问码不进入
`Page.data`、本地存储或日志；只在入口参数及请求所需的内存中使用。只有有限期会话落本地存储。
新扫码优先于旧会话；迟到或页面已卸载的授权结果不写入存储，并尝试撤销无用会话。
切换成功后尝试撤销之前的会话；旧服务离线时不阻止进入新打印机，旧令牌仍等到期或重启失效。
网络失败可以直接重试同一入口，无需再扫码。取消更换时保留原会话。

## 兼容和验收

尚无已发布客户端版本。v1 地址码不能完成自动授权，明确提示部署者重新生成，
不回退到手工输入表单。现有 `/api/v1/sessions` 请求/响应和本地会话存储结构不变。

本地测试验证生成请求经客户端真实解析器还原、自动授权跳转、冷/热启动、重复进入、
旧会话覆盖、新旧请求竞态、取消、重试、过期、微信接口失败及不覆盖既有图片。
微信接口使用模拟响应，生成测试图片不是有效微信入口码。真实账号出码、
模拟器渲染、手机请求和正式版非开发者扫码仍须单独验收。
