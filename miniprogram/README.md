# 微信客户端

M1 已实现扫码进入、微信原生隐私确认、打印机列表及能力、刷新、扫码更换和退出。用户不填写地址或配对码。
现在可从微信聊天选择单个文档/图片，或从相册取图，在打印设置页查看页数、翻页和放大。
打印设置生成最终纸面预览，确认后提交任务；任务页支持查看、取消和手动双面翻纸确认。
真实微信出码、扫码、聊天选文件和手机网络仍待验收。
原生 TypeScript 工程，按需使用 TDesign 组件。未导入商城或管理后台模板的业务代码。

## 开发

需要 Node.js 22 或更高版本，以及微信开发者工具。在本目录运行：

```sh
npm ci --ignore-scripts
npm run setup
npm run check
npm test
```

`setup` 只在缺少配置时复制 `project.config.example.json`，不覆盖已有配置，
并把 TDesign 包自带的原生组件和内嵌依赖准备到 `src/miniprogram_npm/`。
完成后直接用微信开发者工具导入本目录、编译即可；无需先通过 CLI 开启服务端口来生成组件。
后续更新依赖也要运行 `npm run setup`，或者仅运行 `npm run prepare:components`。
准备脚本只处理当前 TDesign 的预编译原生目录，不代替其他 npm 包可能需要的官方构建步骤。
开发工具“工具 -> 构建 npm”仍可用于标准 npm 构建。
本地 `project.config.json` 和 `project.private.config.json` 均被 Git 忽略。
示例使用 `touristappid`；真实 AppID 只填本地配置，AppSecret 不需要也不能进入客户端。

如果启动时提示 `tdesign-miniprogram/input/input` 路径下找不到组件，说明运行目录的组件未准备。
在本目录执行 `npm run setup` 后重新编译；仅仅在 `node_modules` 安装成功还不够。
`npm test` 会检查页面使用的组件在实际运行目录中是否完整，CI 也会从安装到准备执行同一流程。

服务部署者按 [开发说明](../docs/development.md) 设置监听地址和独立的打印访问码，
生成打印机旁的小程序码。普通用户从微信“扫一扫”进入，按需在微信原生弹窗同意隐私指引后显示打印机。
直接打开小程序时，有会话就恢复打印机页，没有会话则显示扫码按钮。

## 连接与会话

- 扫码解析入口后，通过 `services/privacy` 调用 `wx.requirePrivacyAuthorize`，
  成功后才检查服务、获取 `wx.login` code 并交换会话；没有独立登录按钮或自制授权弹层。
  `pages/connect/index` 是已生成小程序码的入口路由，不要求用户在小程序里再扫一次码。
  有目标时只显示加载或失败重试；仅没有目标的直接打开才显示扫码入口。
- 隐私同意使用微信官方弹窗，指引入口调用 `wx.openPrivacyContract`。需要基础库 2.32.3+
  及微信后台正确配置的隐私指引；拒绝或接口不支持时不登录。微信已记录有效同意时不重复弹窗。
- 码中的打印访问凭据不进入页面渲染数据、本地存储或日志；在请求和重试所需的内存中使用。
- 客户端保存服务地址、有期限的会话令牌及过期时间。请求统一经过 `services/`。
- 授权过期后重新扫码；schema 2 服务重启保留未到期会话。网络错误可重试，CUPS 失败不误删会话。
- “退出”仅在“我的”，撤销服务端会话并清除本地连接；服务离线时可单独选择“仅退出本机”，
  这不等于已经远程撤销令牌，原令牌会在到期或部署者更换访问码时失效。
- 新扫码优先于缓存的旧打印机；切换成功后尝试撤销原会话，取消扫码则保留原会话。
- 队列的“空闲”和“接受任务”是 CUPS 报告，不代表有纸或设备已经输出纸张。

## 生成打印码

以下是部署者操作，不是普通打印用户的操作。在本目录运行：

```sh
npm run printer-code -- --server http://printbridge.example.test:8080 --env trial
```

运行前由部署者在本地环境设置：

- `PRINTBRIDGE_PAIRING_CODE`：与正在运行的服务配置一致的独立打印访问码。
- `WECHAT_ACCESS_TOKEN`：对应小程序的有效服务端 access token，不是 AppSecret 或用户会话令牌。

不要把真实凭据写进命令参数、项目配置或源码。默认保存到仓库根目录被忽略的 `data/printer-code.png`
或 `.jpg`，后缀按微信返回的格式确定。已有文件不会被覆盖，可用 `--output ../data/printer-code-next`
指定新的无后缀文件名。`--env` 可选 `release`、`trial`、`develop`，默认 `release`。
示例域名需换成手机可访问的服务地址；`127.0.0.1` 只适用于本机测试。

隔离访客网可以增加 `--alternate-server http://172.22.60.1:8080`，
同时把主地址换成对应主网的私有 IPv4 origin。最多三个备用地址，所有地址必须为私有 IPv4，
且不能重复。隐私同意后按手机地址与真实子网掩码选择唯一同网段入口，不向其他入口试发凭据。
网络不匹配时连接正确 Wi-Fi 后点重试；已经连接后换 Wi-Fi 需要重新扫码。
网关打印端口映射与隔离由部署者配置，见 [部署说明](../docs/deployment.md)。

工具调用微信 `getwxacode`，将入口参数写入小程序码。成功只输出图片位置，失败不保存“二维码”。
网络、token、账号权限或版本错误会明确失败；当前没有使用真实账号完成出码验证。
实际扫码和网络访问仍受小程序账号、版本、网络等运行条件影响，须用手机验收。

## 入口契约

路径为 `pages/connect/index?entry=<encodeURIComponent(JSON)>`，JSON 为：

```json
{"type":"printbridge","version":2,"server":"http://printbridge.example.test:8080","pairingCode":"test-only-pairing-code-0123456789012345"}
```

此处凭据是合成测试值，部署时由工具读取实际服务配置。二维码是可重复使用的打印入口，
持有码者可以申请该 PrintBridge 服务的访问会话；它不是管理员密码。

v2 还接受可选 `"alternateServers":["http://172.22.60.1:8080"]`。
使用此字段时 `server` 也必须是私有 IPv4 地址；生成工具检查入口总长度。
新客户端兼容单地址码，旧客户端会拒绝含新字段的码，需先更新客户端再更换码。
地址选择仅影响本次新授权，不将已保存令牌自动发送到另一 origin。
兼容与安全边界见 [ADR 0024](../docs/decisions/0024-guest-network-and-local-entry.md)。

开发工具可用同一路径及编码后的 `entry` query 测试扫码入口和原生隐私确认。小程序内扫码同时接受微信返回的
当前小程序 path 和上述 JSON 普通二维码。JSON 普通二维码仅供局部调试，不能声称它会从微信外部
打开小程序。v1 只含地址的旧码会提示更新，不再回退到手工配对；scene 短码暂不支持。
完整决定与平台证据见 [ADR 0004](../docs/decisions/0004-scan-entry.md)。
微信原生隐私授权的新约定见 [ADR 0017](../docs/decisions/0017-explicit-login-and-inline-profile.md)。

开发工具模拟扫码的启动项使用上述单地址 `entry`，不要加入 `alternateServers`；
`server` 明确填电脑当前可达的打印入口。电脑插网线时可直接使用主网服务地址。
现场 Stable v2.01.2510290 / 基础库 3.17.4 的 `wx.getLocalIPAddress` 返回虚拟网卡地址且缺少
`netmask`，无法作为电脑实际路由依据；HTTP 直连成功也可能停在“无法读取当前 Wi-Fi 网络”。
手机多网络码仍需真实地址和掩码，需单独用手机验证，不能用模拟器结果替代。

## 目录约定

- `pages/` 组织页面状态和交互，不包含打印页序算法。
- `components/` 放重复使用的预览、参数和翻纸控件。
- `services/` 统一处理 API、上传、轮询及网络错误；以 `../api/openapi.json` 为契约。
- 文件引用服务端文档编号。返回页面、翻页和轮询不得重新上传同一份文档。
- 真实 AppID 及个人开发者工具配置保留在本地，公开仓库使用可复制的示例配置。
- 管理员凭据和小程序 AppSecret 不打包进客户端。

真机验证需要覆盖选文件、局域网连接、前后台切换以及重新进入后恢复任务。
启用微信身份后，新会话通过服务端稳定账号恢复同一用户的任务；匿名模式仍按会话区分，
新会话不认领旧匿名任务。不能把预览版或开发者身份测试当成普通用户正式版验收。

“我的”提供页内自愿姓名输入及保存，清空后保存即可删除姓名，不弹出首次填写或编辑弹窗。
展示的“打印账户编号”为本服务随机内部 ID，原始 OpenID 只在服务端用于映射，不下发客户端。

`npm test` 检查服务请求、会话和页面状态，使用模拟 `wx`，不等于微信运行时验证。
开发工具和手机验证范围见 [M1 验证记录](../docs/verification/2026-10-14-m1.md)。

## 文件与打印

打印机列表点击“选择文件”，从微信聊天选择单个文档/图片，或从相册取图。
相册选择明确限定 `sourceType: ['album']`，首次选择和更换图片均不提供拍照入口。
手机文件管理器内的本地文档导入尚未实现。微信公开的
[`wx.chooseMessageFile`](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.chooseMessageFile.html)
选择客户端会话文件；开发工具模拟该接口时打开电脑文件框，不代表手机支持系统文档选择。
当前可先将本地文档发送到文件传输助手，再从聊天文件选择；独立本机导入仍待确定接入方式。
原文件最多 20 MiB，转换结果最多 128 MiB / 500 页。选择页仅负责选文件和上传，
上传成功后替换为打印设置页，在同一页预览并调整纸张、份数、范围、奇偶、倒序、颜色、
方向、缩放、多页合一和双面；返回直接回到打印机列表。
右上角“重新上传”在当前设置页选择聊天文件或相册图片；上传成功后替换当前文档，
恢复默认打印参数，重新生成预览。取消选择或上传失败保留原文档、设置和预览，
不额外压入页面。客户端一次编辑一个文件，不提供多文件收件箱或批量提交。
预览只创建排版，不打印；修改设置自动更新预览，最新预览成功前不可打印。
打印按钮确认后才创建任务，重复点击、网络重试沿用本地保存的幂等键。
分页失败只重新请求这一页；翻页、放大、返回前台均不重复上传文档。
上传失败后可手动重试，响应丢失时服务端可能保留两份文档，均不会打印且到期自动清理。

`services/documents.ts` 统一调用 `wx.chooseMessageFile`、仅限相册的 `wx.chooseMedia`、`wx.uploadFile`、
带 Authorization 的 `wx.downloadFile`，页面不直接发网络请求。放大使用下载到本地的分页图；
图片 URL 不携带凭据。本地最多保留六张预览，页面卸载时中止上传/下载并清除这些文件。
原始微信聊天文件属于微信临时文件，不由本项目删除。

项目自己的 WXSS、WXML 尺寸属性使用 rpx，百分比及 vh 用于比例和视口约束。
不修改 TDesign 包内部样式。界面组织参考 cups-web，未复制其 Vue 组件实现。
正式环境需要同时验证 request、uploadFile、downloadFile 的服务域名、HTTPS 和网络权限；
开发工具的本机调试配置不证明手机可以访问。

“打印任务”可重新打开当前会话的任务。任务页在前台轮询，后台或卸载停止轮询。
手动双面的翻纸方式由部署者在服务端按队列配置，见 [部署说明](../docs/deployment.md)。
普通用户只选择单双面和装订边，不显示首轮纸面、第二轮顺序、旋转或校准确认。
当前 `rear-face-up-v1` 方案默认先倒序偶数面、再倒序奇数面。
三页文档为第一轮“空白、2”，第二轮“3、1”；空白纸也要整叠放回。
设置页和等待翻纸时共用三步示意；长边和短边装订使用同一放纸动作，
第二轮的图像方向由服务端按装订边及横纵方向处理。
第一轮后必须勾选纸张已完全输出并翻好放回，
才能继续第二轮。CUPS 完成不直接等同于物理出纸完成。
方案与解析后的参数随任务固定，旧任务沿用旧参数；本机旧校准缓存不再影响新设置。
未配置或不认识的方案不提供手动双面，不自动套用其他设备参数。
不确定提交会显示核对状态及取消入口，不提供自动重打按钮。
